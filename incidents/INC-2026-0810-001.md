# Incident Report: mongo-cxx-driver 4.4.1 Deprecation Warnings

## Summary

Compiling `mongo-cxx-driver` 4.4.1 (as a Meson `cmake.subproject()`) against
`mongo-c-driver` 2.4.0 produces a batch of `-Wdeprecated-declarations` warnings
originating from the driver's own private compatibility shim
(`src/mongocxx/lib/mongocxx/private/mongoc.hh`). No functional impact; build
completes successfully.

## Environment

- **mongocxx**: 4.4.1 (static, built via Meson CMake subproject)
- **mongoc (C driver)**: 2.4.0, installed at `/opt/mongo-c-driver/current`
- **Build system**: Meson + `cmake` module
- **Compiler**: GCC (per warning format)

## Root Cause

`mongoc.hh` uses a macro, `MONGOCXX_PRIVATE_MOCKED_EXPORT`, to generate
`constexpr` aliases for a fixed list of C-driver symbols:

```cpp
#define MONGOCXX_PRIVATE_MOCKED_EXPORT(name) \
    constexpr auto name = mongoc_##name;
```

mongo-c-driver 2.4.0 renamed its In-Use Encryption **Text Indexes** API from
the `..._encrypt_text_opts_*` / `..._encrypt_text_substring_opts_*` /
`..._encrypt_text_suffix_opts_*` naming to `..._encrypt_string_opts_*` /
`..._encrypt_string_substring_opts_*` / `..._encrypt_string_suffix_opts_*`,
marking the old `text_*` symbols `MONGOC_DEPRECATED`.

mongo-cxx-driver 4.4.1's private header still references the old `text_*`
symbol names, so every mock-export of one of those functions triggers
`-Wdeprecated-declarations`. This is upstream lag on the cxx-driver's part
following the c-driver rename — not a bug in application code, and not a
sign of an unsupported version pairing.

## Compatibility Check

mongo-cxx-driver 4.4.0+ officially requires mongo-c-driver **2.3.1 or newer**.
mongoc 2.4.0 satisfies this — the pairing is supported. The deprecation
warnings are cosmetic build noise, not a compatibility break.

## Affected Symbols

- `mongoc_client_encryption_encrypt_opts_set_text_opts`
- `mongoc_client_encryption_encrypt_text_opts_destroy`
- `mongoc_client_encryption_encrypt_text_opts_new`
- `mongoc_client_encryption_encrypt_text_opts_set_case_sensitive`
- `mongoc_client_encryption_encrypt_text_substring_opts_new`
- `mongoc_client_encryption_encrypt_text_substring_opts_set_str_max_length`
- `mongoc_client_encryption_encrypt_text_substring_opts_set_str_max_query_length`
- `mongoc_client_encryption_encrypt_text_substring_opts_set_str_min_query_length`
- `mongoc_client_encryption_encrypt_text_suffix_opts_destroy`
- `mongoc_client_encryption_encrypt_text_suffix_opts_new`
- `mongoc_client_encryption_encrypt_text_suffix_opts_set_str_max_query_length`
- `mongoc_client_encryption_encrypt_text_suffix_opts_set_str_min_query_length`

## Fix Applied

Suppressed the warning at the subproject level only, via Meson's
`append_compile_args()` on the CMake subproject options, so the project's
own targets keep full `-Wdeprecated-declarations` visibility.

```meson
mongocxx_opts = cmake.subproject_options()
mongocxx_opts.add_cmake_defines({
                                  'CMAKE_PREFIX_PATH' : '/opt/mongo-c-driver/current',
                                  'BUILD_SHARED_LIBS' : 'OFF',
                                  'BUILD_SHARED_AND_STATIC_LIBS' : 'OFF',
                                  'NEED_DOWNLOAD_C_DRIVER' : false,
                                  'CMAKE_BUILD_TYPE' : 'Release',
                                  'ENABLE_TESTS' : 'OFF',
                                  'ENABLE_UNINSTALL' : 'OFF',
                                  'ENABLE_EXAMPLES' : 'OFF'
                                })
mongocxx_opts.append_compile_args('cpp', '-Wno-deprecated-declarations')

mongocxx = cmake.subproject(
  'mongo-cxx-driver',
  options : mongocxx_opts
)
mongocxx_dep = mongocxx.dependency('mongocxx_static')
bsoncxx_dep = mongocxx.dependency('bsoncxx_static')
```

**Result:** Confirmed suppressed on rebuild.

## Caveats / Follow-up

- Requires Meson ≥ 0.55 for `append_compile_args()` on `subproject_options`.
- This is a suppression, not a fix — revisit once mongo-cxx-driver ships a
  release that migrates its private header off the `text_*` symbol names.
- Track upstream: check mongo-cxx-driver GitHub issues / JIRA for a fix
  aligning with mongoc 2.4.0's `string_*` rename.
